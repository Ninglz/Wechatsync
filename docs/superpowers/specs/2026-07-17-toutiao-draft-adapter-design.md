# 头条号草稿适配器设计

## 目标

为公开构建的 WechatSync 扩展补齐 `toutiao` 平台适配器，使已登录的头条号可从扩展 CLI/MCP 接收文章，并保存为头条号后台草稿。

## 边界

- 仅支持头条号后台 `mp.toutiao.com`。
- 仅支持登录检测、正文图片上传、标题/正文写入、保存草稿及返回草稿链接。
- 不调用最终发布、定时发布或提交审核动作。
- 不复制或依赖缺失的 `wechatsync-private-adapters` 子模块。
- 失败时不得留下“已发布”状态；应返回可读错误和已有草稿 ID（如果服务端已返回）。

## 方案比较

1. **新增公开 `ToutiaoAdapter`（采用）**：沿用 `CodeAdapter`、图片处理和 MCP 现有协议。公开构建可复现，平台状态会出现在 `platforms` 和 `publish_content` 中。
2. 恢复官方私有子模块：该仓库对当前访问者不可得，不能作为产品依赖。
3. 仅靠页面内容脚本自动点击：对页面结构脆弱，难以可靠返回草稿 ID，故不采用。

## 架构与数据流

`MCP publish_content(platform=toutiao)` → 扩展 MCP 客户端 → `ToutiaoAdapter` → 头条号已登录会话 → 草稿保存结果。

适配器放在 `packages/core/src/adapters/platforms/toutiao.ts`，导出并在扩展的 `ADAPTER_CLASSES` 中显式注册。它声明 `article`、`draft`、`image_upload` 能力和 HTML 预处理配置。

`checkAuth()` 使用已登录会话访问头条号后台的轻量账户接口；如果返回未登录、账号无创作权限或接口结构改变，明确返回未认证状态。`publish()` 必须先检查认证，再将文章 HTML 中的远程图片逐个替换为头条号上传后的 URL，最后调用“保存草稿”接口。返回值始终标记 `draftOnly: true`，并包含头条号编辑页草稿链接。

头条号真实接口、必填分类和封面字段以本机已登录后台的一次草稿保存请求为准；不得猜测并调用“发布”接口。

## 错误处理

- 未登录/无创作权限：提示用户在 `mp.toutiao.com` 完成登录和开通头条号。
- 图片下载或上传失败：中止保存，返回具体图片错误；不把原始图片 URL 当作成功上传。
- 草稿保存失败：返回服务端错误摘要，不报告发布成功。
- 页面/接口变化：返回“头条号接口已变化，需要重新联调”，保留调试信息但不记录 cookie 或 token。

## 测试与验收

先以测试驱动新增两个离线测试：

1. 注册后 `getAdapter('toutiao')` 能取得能力包含 `draft` 的适配器。
2. 未认证时发布会失败，并且不尝试上传图片或调用保存草稿。

联调只在用户已登录的头条号后台进行：提交一篇带两张正文图片的测试文章，验收标准是返回草稿 ID/编辑链接，后台草稿箱能打开且两图可显示；不得出现公开文章或审核提交记录。

## 风险

头条号接口、分类要求和风控策略可能变化，真实保存接口需在用户现有登录会话中采集验证。该风险不会通过自动发布规避。
